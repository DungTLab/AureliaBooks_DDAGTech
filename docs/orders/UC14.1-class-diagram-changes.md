## 2. Năm lớp cần thêm

Quy ước UML: `+` public, `-` private. Với Java record, các thuộc tính dưới đây là các component có backing field private final; Java tự sinh canonical constructor và accessor cùng tên component. Không vẽ chúng như entity JPA và không thêm getter/setter kiểu Lombok cho record.

### 2.1 OrderStatusValidator

- Package: `com.ddagtech.aureliabooks.service`.
- Loại: class, Spring `@Component`.
- Trách nhiệm: xác định các trạng thái đích của đồ thị xử lý staff và từ chối cạnh chuyển trạng thái không hợp lệ.
- Thuộc tính: không khai báo instance field.

| Method | Description |
| --- | --- |
| `+allowedTargets(current: Order.OrderStatus): List<Order.OrderStatus>` | Return permitted staff transition targets; return an empty list for null or a terminal/non-operational state. |
| `+validateTransition(current: Order.OrderStatus, target: Order.OrderStatus): void` | Throw IllegalStateTransitionException when the target is null or is not in allowedTargets(current). |

Đồ thị mà lớp này thực thi:

| Current status | Allowed targets |
| --- | --- |
| PENDING_PAYMENT | Không có |
| PENDING_CONFIRMATION | CONFIRMED, CANCELLED |
| CONFIRMED | SHIPPING, CANCELLED |
| SHIPPING | DELIVERED |
| DELIVERED | Không có |
| CANCELLED | Không có |
| RETURNED | Không có |

`DELIVERED -> RETURNED` được thực hiện bởi `confirmReturnRestock()`, không phải cạnh được phép truyền qua `transitionStatus()`. `PENDING_PAYMENT -> PENDING_CONFIRMATION` thuộc luồng xác minh thanh toán, ngoài đồ thị staff này.

Source: `D:\SpringBoot\AureliaBooks_DDAGTech\src\main\java\com\ddagtech\aureliabooks\service\OrderStatusValidator.java`.

## 3. Quan hệ cần thêm hoặc chỉnh

Các request/response dùng dependency hoặc association theo cấu trúc thực tế, không dùng composition chỉ vì một phương thức trả về DTO.

| Source | UML relationship | Target | Chi tiết |
| --- | --- | --- | --- |
| OrderStateMachineServiceImpl | Association | OrderStatusValidator | Injected field `-statuses: OrderStatusValidator`. |
| StaffOrderController | Dependency | OrderTransitionRequest | Parameter của `transition(...)`. |
| StaffOrderController | Dependency | ReturnConfirmationRequest | Parameter của `returnRestock(...)`. |
| StaffOrderController | Dependency | RefundConfirmationRequest | Parameter của `refund(...)`. |
| OrderStateMachineService | Dependency | OrderTransitionRequest | Parameter của `transitionStatus(...)`. |
| OrderStateMachineService | Dependency | ReturnConfirmationRequest | Parameter của `confirmReturnRestock(...)`. |
| OrderStateMachineService | Dependency | RefundConfirmationRequest | Parameter của `confirmExternalRefund(...)`. |
| OrderStateMachineService | Dependency | PackagingChecklistDTO | Return type của `getPackagingChecklist(...)`. |
| OrderStateMachineServiceImpl | Dependency | Ba request records và PackagingChecklistDTO | Implementation đọc request và tạo DTO. Có thể ẩn các dependency này nếu đã thể hiện đầy đủ qua interface để tránh rối. |
| PackagingChecklistDTO | Association | OrderTimelineStep | `timeline: List<OrderTimelineStep>`; một DTO tham chiếu `0..*` steps. |
| PackagingChecklistDTO | Dependency | Order | Tham chiếu nested enum `OrderStatus` và `StockRestoreReason`; không phải association tới một Order entity qua component `order`. Component đó có kiểu OrderConfirmationView. |
| OrderTransitionRequest | Dependency | Order | Tham chiếu nested enum `Order.OrderStatus`. |
| OrderStatusValidator | Dependency | Order | Dùng nested enum OrderStatus. |

Giữ realization `OrderStateMachineServiceImpl ..|> OrderStateMachineService` và `StockMutationServiceImpl ..|> StockMutationService`.

Xóa mọi cạnh đang mô tả `StockMutationServiceImpl -> OrderVoucherReleasePort` như một call/dependency trực tiếp của luồng UC14.1. Field thực tế là `vouchers: VoucherService`; implementation xử lý là VoucherServiceImpl. Nếu giữ phạm vi 22 lớp, có thể ghi chú kiểu shared interface ở thuộc tính/mô tả; không đổi kiểu field thành VoucherServiceImpl và không tuyên bố VoucherServiceImpl implements OrderVoucherReleasePort.

Class diagram mô tả cấu trúc tĩnh. Thứ tự gọi, lock/refresh, flush/commit và rollback thuộc sequence diagram/mô tả SDS; không suy ra thứ tự runtime từ các cạnh dependency.

## 4. Đồng bộ các lớp đã có với code hiện tại

Bản sao trong `D:\class_diagram\uc14_1` có một số nội dung trước thay đổi return flow. Ngoài thêm/bỏ lớp, cần sửa các điểm sau khi dựng lại diagram.

| Lớp | Nội dung cần cập nhật |
| --- | --- |
| Order | Thêm giá trị `RETURNED` trong enum OrderStatus nếu diagram hiển thị enum. Giữ PaymentStatus chỉ gồm UNPAID, PAID, REFUNDED. REFUND_PENDING không phải giá trị enum này. |
| OrderStateMachineServiceImpl | `confirmReturnRestock` chỉ nhận từ DELIVERED; sau khi engine hoàn kho, service đặt RETURNED. Refund basis là PAID với số tiền dương và CANCELLED hoặc RETURNED có đủ metadata nhận hoàn. |
| StockMutationServiceImpl | `restoreReturnedOrder` kiểm tra DELIVERED trước khi hoàn kho; skip nếu đã có stockRestoredAt. Không chuyển hoàn hàng từ SHIPPING theo bản sao cũ. |
| StaffOrderController | Controller cho SALE_STAFF và MANAGER; return-restock/refund chỉ SALE_STAFF. Không ghi ADMIN là role được phép trên các endpoint này theo bản sao cũ. |
| OrderQueueSpecification | REFUND_PENDING là filter suy ra từ paymentStatus=PAID và orderStatus thuộc CANCELLED/RETURNED. |
| OrderMapper | `toTimeline` có milestone RETURNED sử dụng stockRestoredAt. `toConfirmation` vẫn đọc snapshot tên/giá/địa chỉ của đơn. |
| OrderTimelineStep | `label` xử lý thêm RETURNED. |
| OrderRepository | Dùng file hiện tại làm nguồn chữ ký/query. Không cần đưa các query timeout/VNPay không phục vụ UC14.1 lên diagram. |

Không sửa code nghiệp vụ chỉ để khớp diagram. Đồng bộ tài liệu/bản sao từ nguồn hiện tại trước.
